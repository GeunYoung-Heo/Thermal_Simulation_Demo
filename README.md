# 실내 열관리 디지털 트윈 데모 — 의약품 물류창고

공간을 스캔해 **포인트클라우드 → SAM3 객체 탐지·재매핑 → 메쉬 재구성 → voxel 열해석 → 배치·운전 최적화**까지 이어지는
디지털 트윈 시스템의 동작을 보여주는 데모 프로그램입니다.

> **최종 질문**: 관리대상 구역(보관 랙)의 온도를 15–25 °C로 유지하려면, 열 관련 기구를 **어디에** 배치하고 **몇 도로** 운용해야 하는가?

의약품 창고는 GDP(Good Distribution Practice) 규정에 따라 실온 보관 품목을 15–25 °C로 보관해야 하고, 창고 전체의 **온도 매핑**
(WHO TRS 961 Annex 9 Suppl. 8 등)이 요구됩니다. 실제 현장을 구하기 어려워 **가상 창고**를 만들고, 센서(스캐너·SAM3)는 시뮬레이션으로
대체했습니다. 그 이후 단계(메쉬, 열 모델, 최적화)는 오직 재구성 결과만 사용하므로 실제 데이터로 바꿔 끼울 수 있습니다.

```
 가상 현장(YAML)          ① 3D 스캔                ② SAM3 + 재매핑              ③ 메쉬 재구성
 ┌──────────────┐   ┌───────────────────┐   ┌────────────────────────┐   ┌──────────────────┐
 │ 랙·라디에이터 │ → │ 12곳 360° RGB-D    │ → │ 2D 마스크 → 다시점 투표 │ → │ TSDF 융합 +       │
 │ 문·충전기 ... │   │ 노이즈/구멍/정합오차│   │ → 3D 클러스터 → ID 부여 │   │ 마칭 큐브, 객체별 │
 └──────────────┘   └───────────────────┘   └────────────────────────┘   └──────────────────┘
                                                                                   ↓
        ⑥ 배치·운전 최적화              ⑤ 열 시뮬레이션                    ④ 열 모델(트윈)
   ┌──────────────────────────┐   ┌─────────────────────────┐   ┌──────────────────────────────┐
   │ 후보 위치 탐색(탐욕+교환) │ ← │ voxel 정상상태 전도      │ ← │ ID 장치 = 설계변수            │
   │ + 운전온도 LP(에너지 최소)│   │ ∇·(k∇T)=0, AMG+CG ~1초   │   │ ID 없는 벽·문·설비 = 경계조건 │
   └──────────────────────────┘   └─────────────────────────┘   └──────────────────────────────┘
```

## 빠른 시작

```bash
git clone git@github.com:GeunYoung-Heo/Thermal_Simulation_Demo.git
cd Thermal_Simulation_Demo
```

**Windows**: `run_app.bat` 더블클릭. 처음 실행하면 가상환경 생성 → 패키지 설치(수 분) → 디지털 트윈 생성(약 30초)까지
자동으로 진행된 뒤 브라우저가 열립니다. 두 번째부터는 바로 열립니다. 종료는 검은 창을 닫거나 Ctrl+C.
(Python이 없다면 [python.org](https://www.python.org/downloads/)에서 3.12를 설치하세요. 3.14는 일부 패키지가 아직 지원하지 않을 수 있습니다.)

`data/`(스캔·메쉬 결과, 약 100 MB)는 저장소에 넣지 않았습니다. 처음 실행할 때 `scripts/build_twin.py`가 같은 시드로 다시 만듭니다.

직접 실행하려면:

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python scripts/build_twin.py      # 스캔 → SAM3 → 메쉬 → 트윈  (data/ 생성, 약 30초)
streamlit run app.py              # 브라우저에서 http://127.0.0.1:8501
```

Python 3.11–3.13에서 동작합니다. (개발 환경: Python 3.12, Windows 11)

### 발표용 시연 순서 (겨울 시나리오, 약 5분)

1. **①→③**: "공간을 스캔하고, SAM3로 열 관련 기기를 찾아 ID를 붙이고, 메쉬로 재구성했습니다."
2. **④**: "라디에이터 4대(RAD-01~04)가 모두 도크(남측) 쪽에 있습니다. 벽·문·충전기는 ID가 없으므로 경계조건입니다."
3. **⑤ 실행**: 북측 랙(RACK-03)이 13.8 °C로 기준 미달, 남측은 25.8 °C로 초과합니다. 만족률은 92.8%입니다.
4. **⑥ 실행** (배치 + 운전온도):

   | 경우 | 범위 만족률 | 최저–최고 | 장치 열량 |
   |---|---|---|---|
   | 현재 배치 · 현재 설정온도(55 °C) | 92.8 % ❌ | 13.9–25.8 °C | 6.7 kW |
   | 현재 배치 · 최적 운전온도 | 93.2 % ❌ | 14.2–25.8 °C | 7.2 kW |
   | **최적 배치 · 최적 운전온도** | **100 % ✅** | 15.5–24.5 °C | **5.5 kW** |

   → "운전온도를 아무리 조정해도 현재 배치로는 안 됩니다. **배치가 문제**였고, 북서·북동 쪽으로 옮기면 에너지도 24% 덜 듭니다."
5. **④에서 직접 편집**: 라디에이터를 추가하거나 옮기거나 끄고 다시 ⑤를 실행해, 시스템이 즉시 반응하는 것을 보여줍니다.

여름 시나리오에서는 냉방기(AC) 2대로는 관리구역의 약 6%만 25 °C 이하가 되고, 최적 배치 3대로는 약 73%, 4대로는 100%를 만족합니다.

## 수정하기

### 현장(가상 창고) 바꾸기: `configs/warehouse.yaml`
- `devices`: **실제로 설치되어 있는** 라디에이터/냉방기의 개수와 위치(벽, 벽을 따라 잰 좌표). 바꾼 뒤 `python scripts/build_twin.py`를 다시 실행하거나 앱 사이드바의 *파이프라인 재실행*을 누릅니다.
- `racks`, `doors`, `equipment`: 랙 열, 출입문, 발열설비(충전기·분전반).
- `scanner.stations`: 스캔 위치. 줄이면 가려진 구멍이 늘어납니다.

### 앱에서 바꾸기 (재스캔 없이)
- **장치 개수/위치/온도**: ④ 장치 표에서 행 추가/삭제, x·y·z·방향·설정온도 편집. 새 장치는 같은 종류의 재구성 메쉬를 템플릿으로 3D에 표시됩니다.
- **경계조건**: ④ 경계조건 표. 유형 `convective`(외기온도 T + 열관류율 U), `fixed`(표면온도 고정), `adiabatic`(단열).
- **장치 허용 온도 범위**: `thermal.device_types`의 `T_min`/`T_max` (예: 라디에이터 20–75 °C). 최적화는 이 범위 안에서 온도를 고릅니다.
- **시나리오 프리셋**: `thermal.presets`에 원하는 계절/조건을 추가하면 사이드바에 나타납니다.

## 방법 요약

**스캔 시뮬레이션**: 각 스테이션에서 1024×448 등장방형 파노라마를 박스 장면에 레이캐스팅합니다. 거리 비례 노이즈(σ = 4 mm + 0.15 %·r),
3% 누락, 비스듬한 면 측정 실패, 깊이 불연속부 flying pixel, 스테이션별 정합 오차(1.2 cm, 0.08°)를 넣고 3 cm voxel로 통합합니다.

**SAM3 + 재매핑**: 파노라마마다 클래스별 마스크를 만들되 경계 노이즈, 팽창/침식, 작은 객체 미탐지, 신뢰도를 흉내 냅니다.
각 3D 포인트를 모든 파노라마에 투영해 깊이가 일치하면(가시성 검사) 해당 픽셀의 마스크 클래스에 표를 던집니다.
가까운 시점일수록 가중치를 크게 줍니다. 그다음 통계적 이상점 제거, 클래스별 3D 연결요소 분석, 바닥 접촉 같은 기하 사전지식으로
오탐을 걸러내고 ID(RAD-01 …)를 부여합니다. 라벨이 없는 포인트에서는 축 정렬 평면(바닥/천장/4면 벽)을 검출합니다.

**메쉬**: 깊이 파노라마를 5 cm TSDF로 융합(가까운 시점 가중)하고, 마칭 큐브로 표면을 추출한 뒤 관측되지 않은 voxel에 걸친 삼각형(측정 공간과 미관측 공간 사이의 가짜 면)은 제거합니다.
각 정점은 최근접 라벨 포인트의 ID를 물려받아 객체별 파트가 되고, 표시용으로 quadric 간소화합니다.

**열해석**: 셀 크기 h의 유한체적법, 정상상태 전도만 고려합니다.
- 셀 사이 전도율 `G = h·2k₁k₂/(k₁+k₂)`
- ID 장치·발열설비: 고정온도 물체(Dirichlet)
- 외피: `G = h² / (1/U + h/2k)`, 즉 외기온도 T와 열관류율 U에 의한 Robin 조건
- `A·T = B_bc·T_bc + B_body·T_body` 를 대칭 양정치 행렬로 조립해 AMG 전처리 CG로 풉니다 (19만 미지수, 약 1초).

**최적화**
- *운전온도*: 해가 선형이므로 `T(x) = T₀(x) + Σθᵢ Gᵢ(x)`. 장치 수+1번만 풀면 됩니다.
  1단계에서 `min s  s.t. low+m−s ≤ T(x) ≤ high−m+s` (모든 관리구역 셀, θ 허용범위) 를 풀고,
  2단계에서 범위를 지키면서 `min Σ|Qᵢ|` (장치 열량은 θ의 선형함수) 를 풉니다. 둘 다 HiGHS LP입니다.
- *배치*: 벽을 따라 후보 위치(문·랙·설비와 겹치는 곳 제외)를 만들고, 각 후보를 장치 크기의 1 kW 열원으로 본 단위 응답을 한 번씩 계산합니다.
  어떤 조합이든 작은 LP 한 번으로 평가되므로 탐욕 추가 후 1-교환 탐색을 합니다. 마지막에 선택된 위치에 실제 장치(Dirichlet)를 넣고
  운전온도 LP로 정확히 다시 계산합니다.

## 단순화 가정과 한계 (발표 시 밝혀둘 것)

- **전도만 고려**합니다. 공기의 대류·혼합 효과는 *유효 열전도도*(기본 20 W/m·K, 실제 공기 0.026)로 등가 반영했으므로,
  온도 분포의 **경향과 배치 효과**를 보여주는 용도이며 정량 예측용이 아닙니다. 부력에 의한 성층(위쪽이 더 따뜻함)도 나타나지 않습니다.
- 장치는 **표면온도 고정** 물체로, 일사는 **상당외기온도**로 근사했습니다.
- 스캔과 SAM3는 시뮬레이션입니다. 표시되는 IoU는 가상 정답 대비 검증용 수치입니다.
- 랙은 탐지된 경계상자(AABB)를 화물 재질로 채워 모델링하고, 미분류 잡동사니(지게차, 바닥 팔레트)는 열해석에서 공기로 취급합니다.
- 배치 탐색은 탐욕+교환 휴리스틱이라 전역 최적을 보장하지 않습니다.

## 실제 데이터로 교체하려면

| 단계 | 바꿀 곳 | 필요한 형식 |
|---|---|---|
| 스캔 | `scanner.scan()` 대신 실제 포인트클라우드·이미지·카메라 포즈 로드 | `ScanData` (points, colors, 이미지, 깊이, 포즈) |
| SAM3 | `segmentation.simulate_sam3()` 대신 실제 SAM3 출력 | 이미지별 `det_map`(픽셀→탐지 인덱스) + `detections`(클래스·점수) |
| 이후 | 그대로 사용 | 다시점 투표 → 클러스터링 → TSDF → 트윈 → 열해석 → 최적화 |

투영 모델은 등장방형 파노라마 기준(`PanoGeometry.project`)이므로, 핀홀 카메라를 쓰려면 이 함수만 바꾸면 됩니다.
